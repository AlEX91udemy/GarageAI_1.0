# GarageHub — Дневник авто и ремонта

Мультиавтомобильный дневник техобслуживания и ремонта с AI-диагностикой.

## История аудита и исправлений

В рамках последнего цикла разработки был проведён полный аудит кодовой базы и внедрены критические исправления. Ниже описаны основные этапы работы.

### 1. Аудит кодовой базы
*   **Анализ инфраструктуры:** Проверка конфигурации Vite, TypeScript (`tsconfig.json`), переменных окружения (`.env.example`) и серверной логики (`server.ts`).
*   **Проверка управления состоянием:** Ревизия синхронизации React-состояния (`src/App.tsx`) с бэкендом (API), включая списки запчастей, задачи "To-Fix" и этапы тюнинга.
*   **Безопасность:** Поиск уязвимостей в аутентификации и утечек данных в UI.

### 2. Выявленные и исправленные проблемы

#### 🔴 Критические исправления (Backend & Security)
*   **Конфигурация Gemini:** Убраны захардкоженные имена моделей в `server.ts`. Теперь версия модели управляется через переменную окружения `GEMINI_MODEL` в `.env`.
*   **Безопасность UI:** Удалена кнопка-подсказка с демо-паролем администратора (`admin123`) из `DataSyncBackupModal.tsx`. Мастер-ключ задаётся только на сервере.
*   **Синхронизация данных:** Исправлена потеря данных при перезагрузке страницы.
    *   Добавлена загрузка этапов тюнинга (`tuningStages`) с сервера.
    *   Настроена отправка обновлений регламента ТО (OEM Schedule) на бэкенд.
    *   Реализовано сохранение статуса выполнения задач (`To-Fix`) в базе данных, а не только в локальном стейте.

#### 🟠 Исправления логики и UX (Frontend)
*   **Генерация ID:** Заменена ненадёжная генерация ID через `Date.now()` на `crypto.randomUUID()` для запчастей, задач и автомобилей (исключение коллизий).
*   **Модальные окна:** Устранено дублирование обработчиков `Escape` и конфликты фокуса (`useModalFocus`).
*   **Мобильная версия:** Заменены захардкоженные данные (расходы, последняя заправка) на реальные расчёты из состояния приложения (`HomeScreen.tsx`, `VehicleProfileScreen.tsx`).
*   **Учёт запчастей:** Исправлена логика списания деталей со склада при проведении ТО (`AddServiceModal.tsx`, `App.tsx`).

### 3. Версии и коммиты
*   **`fix(audit): fix Gemini model config, OEM schedule sync, garage part IDs, modal focus and mobile stats`** — Основной коммит с пакетом исправлений.
*   *(Текущая работа)* — Реализация вызова `apiCompleteToFixTask` для завершения задач.

## Запуск проекта

**Требования:** Node.js (v18+)

1.  Установите зависимости:
    ```bash
    npm install
    ```
2.  Настройте переменные окружения в `.env`:
    *   `GEMINI_API_KEY` — ключ API Google Gemini.
    *   `ADMIN_SECRET` — мастер-ключ администратора.
    *   `GEMINI_MODEL` — (опционально) модель по умолчанию.
3.  Запустите сервер разработки:
    ```bash
    npm run dev
    ```

## Проверка кода
*   **Линтинг/Типизация:** `npm run lint` (TypeScript)
*   **Тесты:** `npm test` (Vitest)
