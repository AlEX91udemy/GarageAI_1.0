# Garage AI — Дневник авто и ремонта

Garage AI — веб-приложение для ведения цифрового гаража: автомобили, пробег, обслуживание, заправки, склад запчастей, напоминания и проекты тюнинга. Приложение работает в веб- и мобильном режиме, поддерживает гостевое локальное использование и авторизацию с отдельным гаражом для каждого аккаунта.

## Возможности

* карточки автомобилей с VIN, пробегом, фотографиями и 3D-моделями;
* история сервисных работ, расходы на обслуживание и автоматическое обновление пробега;
* учёт топлива, расчёт расхода и статистика затрат;
* склад запчастей с остатками, совместимостью и списанием при установке;
* задачи «To-Fix», заводские регламенты ТО, напоминания и этапы тюнинга;
* резервное копирование и восстановление данных с проверкой ссылок между записями;
* AI-сканирование чеков и документов через Google Gemini, Google Document AI или OpenRouter;
* локальный OCR на Tesseract.js с русским и английским языками, подготовкой изображений и ограничением размера входных файлов;
* мобильный сканер штрихкодов, QR-кодов деталей и VIN.

Сканер чеков извлекает продавца, дату, итоговую сумму, топливо, работы и запчасти. Результат перед сохранением можно проверить и отредактировать. Для документов доступны облачный OCR и локальный резервный проход; качество зависит от модели, освещения и качества фотографии.

Сервер использует атомарное JSON-хранилище с изоляцией данных пользователей, HttpOnly-сессии, CSRF-проверку, ограничения размера изображений и таймауты внешних AI-запросов. Для production рекомендуется вынести данные и сессии из репозитория, задать явные модели и ключи провайдеров и настроить резервное копирование.

### Краткий анализ сканирования и OCR

Для проверки камеры и распознавания выполнен прогон 50 чеков и 100 документов из открытых наборов данных через OpenRouter с моделью `google/gemini-2.5-flash`. По чекам корректно распознано 189 из 200 проверяемых полей (94,5%); успешный JSON получен для всех 50 образцов. По документам совпало 9 665 из 15 662 значимых слов (61,71%); JSON разобран в 99 из 100 случаев. Все 150 запросов получили HTTP 200. Фактическая стоимость прогона составила около $0,1013.

На том же наборе из 100 документов предыдущая модель `google/gemini-2.5-flash-lite` показала 40,68% совпадения текста; прирост составил около 21 процентного пункта. `gemini-2.5-flash` показывает лучшие результаты на этих тестах, но при более высокой стоимости. Для документов сохраняется рекомендация проверять распознанные данные перед сохранением. Подробный отчёт: `artifacts/ocr-benchmark-report.json`; сценарий проверки: `scripts/ocr-benchmark.mjs`.

Дополнительно сравнили три модели на одинаковых 20 документах: `google/gemini-2.5-flash` — 60,60% совпадения слов, `qwen/qwen3-vl-235b-a22b-instruct` — 60,30%, `google/gemini-2.5-pro` — 42,35%. Pro стоила около $0,34 за 20 страниц, поэтому для OCR невыгодна. Бесплатная `dots-studio/dots-3-note-preview:free` не завершила пробный запуск. Ни одна проверенная модель не подтвердила цель 90%; для дальнейшего роста нужны улучшение/разбиение изображения и отдельный OCR-движок либо тест на документном датасете с полноценной OCR-разметкой. Сравнение: `artifacts/document-model-comparison.json`; сценарий: `scripts/compare-document-models.mjs`.

### Гибридный OCR Google Document AI + Gemini

Для документов `scripts/ocr-benchmark.mjs` поддерживает гибридный режим: Google Cloud Document AI сначала извлекает полный оптический текст страницы (`document.text`), после чего Gemini через OpenRouter получает изображение и этот текст для структурированного JSON-ответа. Если Google credentials, процессор или права недоступны, сценарий автоматически использует JPEG-тайлы и OpenRouter без остановки бенчмарка. Чеки продолжают обрабатываться через текущий маршрут OpenRouter.

Для включения Google Document AI задайте в `.env`:

```text
GOOGLE_CLOUD_PROJECT=garageai-512320
DOCUMENT_AI_LOCATION=eu
DOCUMENT_AI_OCR_PROCESSOR_ID=<id OCR-процессора>
DOCUMENT_AI_RECEIPT_PROCESSOR_ID=<id процессора чеков, опционально>
```

Авторизуйте Application Default Credentials под аккаунтом Google Cloud, которому выдана роль `Document AI API User` (`roles/documentai.apiUser`):

```powershell
gcloud auth application-default login
```

Если `gcloud` не добавлен в `PATH`, используйте полный путь к `gcloud.cmd`, например:

```powershell
& "D:\Users\user\AppData\Local\Google\Cloud SDK\google-cloud-sdk\bin\gcloud.cmd" auth application-default login
```

API включается для проекта командой:

```powershell
gcloud services enable documentai.googleapis.com --project=garageai-512320
```

Короткий прогон на 10 чеках и 10 документах:

```powershell
$env:NODE_TLS_REJECT_UNAUTHORIZED="0"
$env:BENCH_RECEIPT_LIMIT="10"
$env:BENCH_DOCUMENT_LIMIT="10"
node scripts\ocr-benchmark.mjs
```

Отчёт сохраняется в `artifacts/ocr-benchmark-report.json`. Последний проверенный прогон на 10 чеках и 10 документах дал 95% по полям чеков (`38/40`) и следующие метрики FUNSD:

| Режим | Совпадение слов | WER | CER |
| --- | ---: | ---: | ---: |
| `geminiOnly` | 59,75% | 0,62 | 0,42 |
| `hybrid` (Document AI `document.text` + Gemini) | 59,62% | 0,62 | 0,43 |
| `rawDocumentAi` | 59,42% | 0,64 | 0,45 |
| `tesseractFallback` | 34,95% | 0,79 | 0,61 |

В этом прогоне все 10 запросов к OpenRouter получили HTTP 200 и были разобраны как JSON. Ошибочные запуски Google Document AI исключаются из агрегата `rawDocumentAi`, а их `status` и `error` сохраняются в телеметрии каждого документа. Tesseract Worker завершается через `try/finally`.

#### Эксперимент со структурированным контекстом

В отдельной ветке `experiment/structured-hybrid` проверен режим `hybridStructured`: строки Document AI группируются по страницам и колонкам, сортируются по координатам и передаются Gemini как JSON-layout. На той же выборке он дал 59,55%, то есть не превысил `geminiOnly`. Эксперимент сохранён коммитом `e03230a` и не включён в production или основную ветку.

#### Form Parser R&D

Для извлечения бизнес-полей (VIN, госномер, даты и суммы) планируется отдельный процессор Form Parser. Он подключается только после задания `DOCUMENT_AI_FORM_PROCESSOR_ID` в регионе `eu`:

```text
DOCUMENT_AI_LOCATION=eu
DOCUMENT_AI_FORM_PROCESSOR_ID=<id Form Parser>
```

Будущий benchmark будет сравнивать пары «ключ-значение», confidence и fallback на текущий OCR + Gemini. Эти показатели не смешиваются с FUNSD word-accuracy и не считаются подтверждёнными до отдельного прогона.

Изолированный сценарий `scripts/form-parser-benchmark.mjs` уже подготовлен. Он использует 10 чеков SROIE по умолчанию, сохраняет пары `fieldName -> fieldValue`, confidence и совпадение с эталонными полями в `artifacts/form-parser-benchmark-report.json`. До создания процессора сценарий завершается без сетевого вызова со статусом `not_configured`:

```powershell
$env:FORM_BENCH_LIMIT="10"
node scripts\form-parser-benchmark.mjs
```

После создания Form Parser в GCP добавьте ID только в локальное окружение и повторите запуск:

```text
DOCUMENT_AI_LOCATION=eu
DOCUMENT_AI_FORM_PROCESSOR_ID=<id Form Parser>
```

## Запуск проекта

**Требования:** Node.js (v18+)

1.  Установите зависимости:
    ```bash
    npm install
    ```
2.  Настройте переменные окружения в `.env`:
    *   `GEMINI_API_KEY` — ключ API Google Gemini.
    *   `GEMINI_MODEL` — (опционально) модель по умолчанию.
    *   `OPENROUTER_API_KEY` — общий резервный ключ OpenRouter.
    *   `OPENROUTER_RECEIPT_API_KEY` и `OPENROUTER_DOCUMENT_API_KEY` — отдельные ключи для чеков и документов; если не заданы, используется общий ключ.
    *   `OPENROUTER_RECEIPT_MODEL` и `OPENROUTER_DOCUMENT_MODEL` — модели для соответствующих сценариев.
    *   `GARAGE_DB_FILE` — (опционально) путь к изолированному JSON-хранилищу.

При первом запуске приложение открывает гараж в гостевом режиме без обязательного входа. Данные сохраняются локально; авторизация доступна из профиля для синхронизации с сервером. После входа каждый аккаунт получает свою сессию в HttpOnly cookie и отдельный гараж, данные разных аккаунтов не смешиваются. Старый data/garage_store.json сохраняется как архив демо-данных и автоматически не привязывается к новому пользователю.
3.  Запустите сервер разработки:
    ```bash
    npm run dev
    ```
