# Оценка готовности Garage AI

Дата оценки: 21 октября 2026 года.

## Итог

Проект пригоден для локального запуска, демонстрации и дальнейшей разработки. К production-развёртыванию для реальных пользователей не готов без устранения рисков хранения данных, уточнения работы гостевого режима и подготовки эксплуатационной инфраструктуры.

## Результаты проверок

- `npm run lint` — успешно.
- `npm test` — успешно: 12 файлов, 75 тестов. Во время запуска тестов выводятся два ответа API `401 Unauthorized`.
- `npm run build` — успешно. Vite предупреждает о клиентском чанке размером около 694 КБ и создаёт пустой чанк `three`.
- `npm run catalog:audit` — успешно: из 110 конфигураций 100 имеют статус `provisional`, 10 — `partially_verified`, полностью подтверждённых конфигураций нет.
- `npm audit --omit=dev` — уязвимостей в production-зависимостях не обнаружено.

## Риски перед production

1. В Git отслеживаются `data/garage_store.json` и `data/sessions.json`. В них находятся пользовательские данные автомобиля и записи активных сессий с CSRF-секретами. Это создаёт риск раскрытия данных и сохранения сессионного состояния в истории репозитория.
2. Гостевой режим загружает и сохраняет данные в `localStorage`, когда API недоступен или требует авторизацию, но API-записи защищены серверной сессией. Ошибки части операций только журналируются; требуется проверить поведение сохранения и восстановления данных в гостевом режиме.
3. Данные хранятся в JSON-файлах, а сериализация мутаций действует в памяти одного процесса. Для нескольких серверных экземпляров или ненадёжного локального диска нет гарантии согласованной записи.
4. Каталог автомобилей и рекомендации по совместимости не являются авторитетными: для 110 модификаций отсутствуют полные подтверждения конфигурации. TOP-100 также обозначен как предварительный рейтинг.
5. AI-функции зависят от авторизации, корректных API-ключей и доступности внешнего провайдера. Результаты распознавания документов требуют проверки пользователем.
6. Production-сборка проходит, но размер главного клиентского чанка требует проверки на целевых устройствах и сетях.

## Рекомендованные приоритеты

1. Исключить пользовательские данные и сессии из отслеживаемых файлов и определить безопасное обращение с уже сохранённой историей Git.
2. Зафиксировать и проверить ожидаемую модель гостевого режима, включая сохранение изменений и восстановление после перезапуска.
3. Определить целевую платформу и хранилище для production, стратегию резервного копирования и восстановления.
4. Сохранять явную маркировку неподтверждённых автомобильных конфигураций и AI-подсказок; добавлять подтверждения из надёжных источников до использования каталога как технической рекомендации.
5. Провести интеграционную проверку сценариев регистрации, входа, изоляции гаражей, сохранения данных и резервного копирования на целевой платформе.

## Вывод

Текущий статус: **локально работает; к production не готов**. Успешная типизация, тесты и сборка подтверждают базовую техническую работоспособность, но не закрывают перечисленные риски данных, эксплуатации и достоверности каталога.
