## Что добавлено

### Проверки качества и безопасности
- CI workflow выполняет TypeScript check, unit/integration tests, production build, каталоговый аудит, npm audit и Gitleaks.
- Python job проверяет синтаксис и тесты API агентов, затем запускает pip-audit.
- Проверки зависимостей остаются блокирующими: уязвимость не скрывается и не обходится несовместимым принудительным обновлением.

### Изоляция пользовательских данных
- `server/store.test.ts`: тесты изоляции, конкурентной записи, повторной загрузки, защитного копирования и атомарного отклонения повторного логина при гонке регистрации.
- `server/tenant-isolation.integration.test.ts`: HTTP-тесты запрета анонимного доступа, изоляции автомобилей и основных коллекций (напоминания, сервис, топливо, склад, задачи, OEM-регламент и тюнинг), чтения/изменения/удаления, экспорта, некорректного cross-user импорта и конкурентных изменений.
- Дополнительно добавлен и проверен сценарий успешного backup export → reset → import; reset/restore одного пользователя не затрагивает данные другого.
- Добавлена очередь изменяющих HTTP-запросов одного пользователя в пределах одного процесса: следующий запрос получает актуальный snapshot после завершения сохранения предыдущего. Это не координирует несколько экземпляров сервиса.
- Регистрация атомарно отклоняет повторный логин при конкурентных запросах, возвращая HTTP 409.
- Гостевой режим и полный набор сценариев backup/restore пока не закрыты исчерпывающе.

### API агентов
- Для `POST /agents/run` обязателен `AGENTS_API_TOKEN`; отсутствующая серверная настройка закрывает endpoint, отсутствующий/неверный токен отклоняется.
- Добавлены ограничители на стороне Python и Node; в production endpoint отключён без `AGENTS_ALLOWED_USERNAMES`, а запуск разрешён только включённым в allowlist логинам.
- Node backend теперь предоставляет `POST /api/agents/run` и вызывает приватный Python ADK service через `server/agentServiceClient.ts`. В Cloud Run клиент получает ID token через metadata server и дополнительно использует `X-Agents-Token`; в браузер токены не передаются.
- Добавлен типизированный клиент `runGarageAiAgents()` и панель запуска агентов в веб-настройках: выбор ролей, ограничение размера задачи, состояния загрузки/ошибки и безопасный вывод результатов. Backend allowlist остаётся обязательной защитой.
- Добавлены тесты клиента и обработки ответа, ограничение размера upstream-ответа потоковым чтением.
- Контекст для AI-агентов содержит ограниченные фрагменты исходного кода, исключает runtime data и файлы окружения; runner закрывается также при ошибке.
- Автотесты с подменой модели проверяют оркестрацию; они не заменяют реальный вызов Gemini/Vertex AI.

### Подготовка Cloud Run
- Добавлены `Dockerfile`, `agents_service/Dockerfile`, `.dockerignore`, `cloudbuild-agents.yaml`.
- Добавлена инструкция `docs/cloud-run-deployment.md` с требованиями к IAM, Secret Manager, сборке, приватному сервису агентов и smoke-тестам.

## Результаты проверок

- TypeScript check — passed.

- Production build — passed.
- Сборки web и private-agent Docker — passed.

- Gitleaks — passed.
- Python syntax check и **11 Python-тестов** — passed, включая аутентификацию, ограничение запросов и очистку ADK runner.
- Python dependency audit — failed: `opentelemetry-api 1.44.0` flagged for `CVE-2026-114603`.

**Общий CI остаётся красным** из-за блокирующего `pip-audit`. Исправление OpenTelemetry доступно в `1.45.1`, но опубликованный Google ADK `2.13.0` и текущая upstream-ветка `main` всё ещё ограничивают OpenTelemetry API/SDK версиями `<=1.44`. Проверена актуальная upstream-метаинформация: совместимого опубликованного релиза ADK пока не найдено. Поэтому зависимость не форсируется, ограничения установщика не обходятся, `pip-audit` остаётся обязательным. Необходимо дождаться совместимого upstream-релиза либо отдельно спроектировать замену ADK на SDK без уязвимой зависимости; это изменение архитектуры и требует отдельного плана/проверок.

## Открытые блокеры

1. **Python dependency CVE.** `pip-audit` обнаруживает `CVE-2026-114603` в `opentelemetry-api 1.44.0`. Версия с исправлением конфликтует с ограничением версии в текущем `google-adk==2.13.0`. Нужно дождаться совместимого набора зависимостей и проверить его; не подавлять аудит.
2. **Персистентность.** `server/store.ts` использует JSON-файл. Для масштабирования Cloud Run требуется миграция на управляемую БД и проверка резервного копирования/восстановления.
3. **Реальная интеграция агентов ещё не подтверждена в облаке.** Node → Python service-to-service client реализован с Cloud Run OIDC и вторым токеном, но IAM/Secret Manager, реальный сетевой вызов и Gemini model call не проверены.
4. **Оставшиеся тесты изоляции/восстановления.** Теперь добавлены тесты основных коллекций и отказа при импорте с чужим `vehicleId`; гостевой режим и полный набор успешных/неуспешных backup/restore сценариев ещё не проверены.
5. **Исторические данные в Git.** Удаление `data/garage_store.json` из текущего дерева не очищает прошлые коммиты. Переписывание истории не выполнялось.
6. **Проверка облака.** Не проверены реальный вызов Gemini/Vertex AI, конфигурация IAM/Secret Manager, биллинг и production smoke tests.
