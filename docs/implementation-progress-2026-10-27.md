## Открытые блокеры

1. **Python dependency CVE.** `pip-audit` обнаруживает `CVE-2026-114603` в `opentelemetry-api 1.44.0`. Версия с исправлением конфликтует с ограничением версии в текущем `google-adk==2.13.0`. Нужно дождаться совместимого набора зависимостей и проверить его; не подавлять аудит.
2. **Персистентность.** `server/store.ts` использует JSON-файл. Для масштабирования Cloud Run требуется миграция на управляемую БД и проверка резервного копирования/восстановления.
3. **Интеграция агентов.** Node backend пока не имеет подтверждённого аутентифицированного service-to-service вызова отдельного Python-сервиса.
4. **Полное покрытие изоляции.** Добавленные тесты покрывают автомобили и сервисные записи, но не все ресурсы, импорт/восстановление и гостевой режим.
5. **Исторические данные в Git.** Удаление `data/garage_store.json` из текущего дерева не очищает прошлые коммиты. Переписывание истории не выполнялось.
6. **Проверка облака.** Не проверены реальный вызов Gemini/Vertex AI, конфигурация IAM/Secret Manager, биллинг и production smoke tests.

## Рекомендуемый порядок продолжения

1. Получить итог свежего CI, включая Docker build jobs.
2. Устранить CVE через совместимое обновление ADK/зависимостей и повторить pip-audit.
3. Завершить интеграционные тесты для остальных пользовательских ресурсов, импорта/восстановления и гостевого режима.
4. Спроектировать миграцию JSON-хранилища в managed database и проверить backup/restore.
5. Добавить Node → Python authenticated service-to-service вызов.
6. Только после этого развёртывать тестовую среду Cloud Run, настроить IAM/Secret Manager и выполнить smoke-тесты.
7. Отдельно оценить необходимость удаления исторических данных из Git и согласовать последствия переписывания истории.
